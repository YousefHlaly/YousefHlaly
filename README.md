### KRONOS — Agentic Orchestrator Platform

<a href="https://github.com/YousefHlaly/KRONOS"><img alt="Open the KRONOS repository" src="https://img.shields.io/badge/repo-YousefHlaly%2FKRONOS-0D1117?style=for-the-badge&labelColor=0D1117&logo=github&logoColor=22D3EE" /></a>
<img alt="Status: all six build phases complete" src="https://img.shields.io/badge/status-6%2F6%20phases%20complete-0D1117?style=for-the-badge&labelColor=0D1117&color=0E7490" />
<a href="https://github.com/YousefHlaly/KRONOS"><img alt="KRONOS primary language" src="https://img.shields.io/github/languages/top/YousefHlaly/KRONOS?style=for-the-badge&labelColor=0D1117&color=0D1117&logo=python&logoColor=22D3EE" /></a>
<a href="https://github.com/YousefHlaly/KRONOS/commits/main"><img alt="KRONOS last commit" src="https://img.shields.io/github/last-commit/YousefHlaly/KRONOS?style=for-the-badge&labelColor=0D1117&color=0D1117" /></a>

> A full-stack, modular platform for building and operating multi-agent systems: multi-agent orchestration with MCP,
> production RAG, a visual canvas, end-to-end data infrastructure and per-agent fine-tuning — local-LLM-first, no mocks.

**The problem.** Agentic systems are usually assembled from vendor SDKs, ad-hoc retrieval code and one-off training scripts.
KRONOS puts orchestration, retrieval, data infrastructure, fine-tuning and observability behind one coherent, typed platform,
and defaults to running entirely on your own machine through Ollama — no API keys, no cost, no data egress — with OpenAI,
Anthropic, Gemini and Mistral available as an explicit, documented opt-in behind a single unified interface.

**Architecture**

| Layer | What it does |
|:--|:--|
| Environment & LLM adapter | One async interface over Ollama, OpenAI, Anthropic, Gemini and Mistral — chat, streaming chat, embeddings, model listing and health, all real HTTP with a typed error model, plus a concurrent environment-diagnostics CLI with a fix path per check |
| Data infrastructure | 12 ingestion sources, 4 chunking strategies, Qdrant vectors alongside BM25, DuckDB analytics and streaming ingestion |
| RAG & memory | Hybrid retrieval fused with reciprocal rank fusion, re-ranking, and layered scoped + episodic memory |
| Orchestrator engine | MCP tools, four agent types under a supervisor, Langfuse tracing, exposed through FastAPI |
| Canvas UI | React Flow graph editor with live run state streamed over Redis Streams and WebSockets |
| Fine-tuning control panel | Real LoRA and DPO training with gated QLoRA/RLHF, evaluations and a model registry |
| Project import & auto-improvement | Static and AST analysis, leakage detection, and an LLM review-and-apply loop |

**Stack** — Python backend · TypeScript, Next.js and React canvas UI · Docker Compose data stack: Qdrant, Redis, PostgreSQL, Redpanda · Apache-2.0

### Sport Performance Analyzer v2 — Pose-Graph Computer Vision

<a href="https://github.com/YousefHlaly/sport-performance-analyzer-v2"><img alt="Open the sport-performance-analyzer-v2 repository" src="https://img.shields.io/badge/repo-YousefHlaly%2Fsport--performance--analyzer--v2-0D1117?style=for-the-badge&labelColor=0D1117&logo=github&logoColor=22D3EE" /></a>
<a href="https://github.com/YousefHlaly/sport-performance-analyzer-v2"><img alt="Primary language of the sport-performance-analyzer-v2 repository" src="https://img.shields.io/github/languages/top/YousefHlaly/sport-performance-analyzer-v2?style=for-the-badge&labelColor=0D1117&color=0D1117&logo=python&logoColor=22D3EE" /></a>
<a href="https://github.com/YousefHlaly/sport-performance-analyzer-v2/stargazers"><img alt="sport-performance-analyzer-v2 stars" src="https://img.shields.io/github/stars/YousefHlaly/sport-performance-analyzer-v2?style=for-the-badge&labelColor=0D1117&color=0D1117" /></a>

> Upload an athlete's attempt and a professional reference clip; get back a calibrated score and a ranked list of
> corrections, each naming a joint, a direction, and a magnitude in degrees.

A full rebuild of the original tool around a **19-joint biomechanical skeleton graph** instead of raw MediaPipe
landmarks — every pose is re-centred on the pelvis, scaled by torso length, rotated upright, and mirrored for footedness,
so camera distance, angle, and handedness stop leaking into the score. Movements of different length and tempo are
matched with **subsequence Dynamic Time Warping** over joint-angle trajectories rather than compared frame-by-index, and
an **adaptive ST-GCN** (2.77M parameters, three-way spatial partitioning, trained with a SimCLR-style contrastive
objective) contributes a learned similarity signal on top of the geometric one — gated off by weight, and disclosed as
such, until enough footage exists to trust it. The service is a Flask job-based API behind a React/TypeScript client,
with a 95-test backend suite plus Playwright end-to-end coverage.

**Stack** — Python · PyTorch · MediaPipe (Tasks API) · OpenCV · Flask · React · TypeScript · Redis · pytest · Playwright
